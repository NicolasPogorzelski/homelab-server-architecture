# lxc211 - Paperless-ngx

Runs Paperless-ngx 3.x (OCR, classification, full-text search) with its database on lxc260 and its
documents on vm102.

- Tag: `tag:tier1`

## Resources

- CTID 211, hostname `paperless`, Debian 12, unprivileged, nesting on
- 2 cores, 2048 MB RAM, 512 MB swap, 10 GB root disk on `local-lvm`
- Onboot, startup order 3; needs lxc260 to be up
- Kernel TUN for Tailscale ([DD-13](../decisions/design-decisions.md#dd-13))

## Services

Docker Compose stack in `/opt/paperless`, source `docker/paperless/docker-compose.yml` (image
versions live there):

| Container | Role |
|---|---|
| `paperless` | web UI, API and Celery workers, `127.0.0.1:8000` |
| `paperless-redis` | task queue and locking |
| `paperless-gotenberg` | Office to PDF conversion |
| `paperless-tika` | text and metadata extraction |

The database is `paperless_db` on lxc260, over TLS to its Tailscale address
([PostgreSQL platform](../services/postgresql-platform.md)). The consumer polls every 30 s and scans
subdirectories, because inotify does not see writes on CIFS. Ingest flow and workflows:
[Paperless-ngx](../services/paperless.md).

## Storage

- `mp0`: `/mnt/smb/paperless` -> `/data/paperless` - originals, thumbnails, consumption and export
  on the vm102 `[Paperless]` share
- `mp1`: `/mnt/aux-disk/paperless` -> `/var/lib/paperless` - logs, `containerd/` and `docker-data/`
  on the aux-disk ([KE-13](../platform/known-errors.md#ke-13))
- No database files on CIFS; PostgreSQL runs on lxc260.

## Access Model

- Paperless binds `127.0.0.1:8000` and is published through `tailscale serve` on 443:
  `https://paperless.<tailnet-id>.ts.net` ([decision](../decisions/loopback-tailscale-serve.md)).
- `lan_guard` drops new inbound LAN connections; sshd binds the Tailscale address.
- Grants are in [tailscale-acl.md](../platform/tailscale-acl.md). The host alias `paperless`, not
  `tag:tier1`, is what reaches `tag:database:5432` and the journal receiver on lxc200.

## Configuration Management

Applied from lxc250. Node-specific roles:

- `paperless_env` - renders `/opt/paperless/.env` from vaulted secrets (`vault_paperless_*`) and
  recreates the stack on change
- `journal_upload` - ships the journal to lxc200
  ([exercise scope](../decisions/exercise-scope-before-terraform.md))
- `tailscale_boot_gate`, `ssh_hardening` - sshd pinned to the Tailscale address
- Group `docker`: `docker_compose_update` (stack listed in `host_vars/lxc211.yml`),
  `docker_boot_retry` and `docker_mount_ordering` (both inactive on this node)

Guest baseline: `apt_metrics`, `journald`, `lan_guard`, `listener_metrics`, `node_exporter`,
`nft_guard` (no ports here), `nsswitch`, `systemd_hygiene`, `timezone`, and the `apt-upgrade.yml`
playbook. See [Ansible](../platform/ansible.md).

## Failure Impact

- No ingestion, search or document access. Uploads through Nextcloud wait in the consumption share.
- Documents on vm102 and metadata on lxc260 are unaffected.
- If lxc260 is down, Paperless does not start; restore lxc260 first.
- Bulk imports of thousands of documents can exhaust the container's memory; raise cores and RAM
  for the import and set them back afterwards.
