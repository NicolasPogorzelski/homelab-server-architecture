# vm102 - Storage

Runs the archive pool: SnapRAID parity over passed-through data disks, a MergerFS union, and Samba
shares segmented per service. It holds the services' file data and the database dumps; database
data directories and Docker state live elsewhere ([storage design](../platform/storage-design.md)).

- Tag: `tag:storage`

## Resources

- VMID 102, hostname `Storage`, Debian 12, virtio-scsi-single, guest agent on
- 2 cores, 4096 MB RAM; onboot, startup order 1
- `scsi0`: 16 GB system disk on `local-lvm`
- `scsi1`-`scsi5`: data disks disk01-disk05; `scsi6`: parity disk; `scsi7`: `aux-pool`; `scsi8`:
  disk06, as large as the parity disk ([adding a data disk](../platform/storage-design.md#adding-a-data-disk))
- All pool disks are passed through by `/dev/disk/by-id/`, so the VM cannot be snapshotted.
- The host's `aux-disk` is not attached to this VM; its fstab carries a do-not-mount note
  ([KE-13](../platform/known-errors.md#ke-13)).

## Services

- MergerFS union at `/mnt/mergerfs` over disk01-disk06 and `aux-pool`
- SnapRAID, single parity. Timers from `snapraid_maintenance` run sync daily, scrub weekly and
  status daily, all `Persistent=true` (schedules and scrub percentage in the role defaults). The
  script writes textfile metrics read by the `SnapRAID*` alerts ([monitoring](../platform/monitoring.md)).
- `storage-permissions.timer` checks share ownership and modes nightly (`StoragePermissionDrift`)
- Samba, SMB3 only, signing mandatory, `smb ports = 445`; `nmbd` masked

| Share | Access |
|---|---|
| `[Nextcloud]`, `[Paperless]`, `[Postgres-backups]`, `[DB-Backups]` | read-write, one service user each |
| `[Paperless-ingest-user1]`, `[Paperless-ingest-user2]` | `paperless-ingest`, scoped to one consumption subdirectory |
| `[media-jf-filme]`, `[media-jf-serien]`, `[media-abs-audiobooks]`, `[media-abs-podcasts]`, `[Books-service]` | read-only, not browseable, one per library |
| `[Filme]`, `[Serien]`, `[Audiobooks]`, `[Books]` | `storage`, read-write, admin workstation |

Share model and identities: [Samba](../platform/samba.md).

## Storage

The pool's content and its protection are in [storage design](../platform/storage-design.md) and
[backup and recovery](../architecture/backup-flow.md). Parity reconstructs a failed disk; it does not
undo deletion, corruption or encryption written by the next sync.

## Access Model

- SMB clients: the hypervisor (bind-mounts shares into the containers) and vm100 over the LAN;
  lxc210's External Storage and the admin workstations over the tailnet
  ([tailscale-acl.md](../platform/tailscale-acl.md)).
- `smbd` listens on `0.0.0.0:445` and `[::]:445`, because Samba cannot bind an IPv4 address on
  `tailscale0` ([SMB bind decision](../decisions/smb-bind-and-lan-access.md)). The nftables table
  `inet smb_guard` (`smb-guard.service`) filters it in the kernel: IPv6 on the LAN interface
  dropped, IPv4 accepted only from vm100 and the hypervisor. Never load it through
  `nftables.service`, whose flush would remove Tailscale's chains.
- `lan_guard` drops every other new inbound LAN connection (`lan_guard_allow` in host_vars admits
  445 from the same two sources).
- sshd binds the Tailscale address only, behind `tailscale_boot_gate`
  ([sshd decision](../decisions/sshd-listen-address.md)). Rollback is the Proxmox web console as
  user `storage`.
- Break-glass: the two admin workstation keys for user `storage`, enforced exclusively by
  `breakglass`.

## Configuration Management

Applied from lxc250. Node-specific roles:

- `snapraid_maintenance` - script, sync, scrub and status timers, `/etc/snapraid.conf` excludes
- `storage_permissions` - share directories on every branch, nightly drift check
- `lan_guard` - with the SMB exception in `host_vars/vm102.yml`
- `systemd_hygiene` - masks `nmbd.service`
- `chrony`, `breakglass` (group `vms`, `breakglass_user: storage`)
- `tailscale_boot_gate`, `ssh_hardening`

Guest baseline: `apt_metrics`, `journald`, `listener_metrics`, `node_exporter`, `nft_guard` (no
ports here), `nsswitch`, `timezone`, and the `apt-upgrade.yml` playbook.

Hand-deployed, not managed by any role: `/etc/samba/smb.conf` (sanitized mirror
`snippets/storage/smb.conf.storage-vm102.sanitized.conf`) and the `smb_guard` table and unit
(`snippets/storage/smb-guard.nft`, `snippets/systemd/smb-guard.service`). See
[Ansible](../platform/ansible.md).

## Failure Impact

- Nextcloud, Paperless-ngx and Calibre-Web lose their data; Jellyfin and Audiobookshelf lose their
  libraries; the database dumps stop. Containers start onto empty bind-mount directories.
- Data is safe while the disks are intact; one failed data disk is rebuilt from parity.
- No high availability; recovery is procedural.
