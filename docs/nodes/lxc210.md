# lxc210 - Nextcloud

Runs Nextcloud as a native stack (Apache, PHP 8.2, MariaDB, Redis) with user data on vm102.

- Tag: `tag:tier1`

## Resources

- CTID 210, hostname `nextcloud`, Debian 12, unprivileged, nesting on
- 2 cores, 2048 MB RAM, 512 MB swap, 15 GB root disk on `local-lvm`
- Onboot, startup order 3

## Services

- Apache on `*:80` and `*:443`, TLS with the on-disk Tailscale certificate (no `tailscale serve`)
- MariaDB on `127.0.0.1:3306` only; `mariadb.socket` is masked by `mariadb_bind`
- Redis on `127.0.0.1:6379` (file locking), APCu (local cache)
- Collabora Online (`richdocumentscode` AppImage) on `*:9983`, reached only through Nextcloud's
  `proxy.php` over loopback; see [Nextcloud](../services/nextcloud.md)

Scheduled work, all systemd timers with `Persistent=true` except the upstream Nextcloud cron:

| Unit | Purpose | Role |
|---|---|---|
| `mariadb-backup.timer` | verified dump to `/mnt/backups`, feeds `MariaDBBackupStale` | `mariadb_backup` |
| `mariadb-restore-test.timer` | monthly restore into a throwaway database, feeds `MariaDBRestoreTestStale` | `mariadb_restore_test` |
| `paperless-inbox-scan.timer` | hourly `occ files:scan` of the Paperless inbox mounts | `paperless_inbox_scan` |
| `tailscale-cert-refresh.timer` | renews the certificate, reloads Apache on change ([KE-16](../platform/known-errors.md#ke-16)) | `tailscale_cert` |
| `/etc/cron.d/nextcloud` | `cron.php` every 5 minutes, upstream-owned | - |

Schedules are in each role's `defaults/main.yml`.

## Storage

- `mp0`: `/mnt/smb/nextcloud` -> `/mnt/nextcloud` - user data on the vm102 `[Nextcloud]` share,
  mounted by the host
- `mp1`: `/mnt/smb/db-backups` -> `/mnt/backups` - MariaDB dumps on the separate `[DB-Backups]`
  share ([MariaDB backup](../../runbooks/database/mariadb-backup.md))
- MariaDB data on the root disk, in the thin pool on the boot disk
- Nextcloud External Storage mounts the two Paperless ingest shares over the tailnet
  ([Nextcloud](../services/nextcloud.md#external-storage-paperless-integration))

## Access Model

- Reached over the tailnet at `https://nextcloud.<tailnet-id>.ts.net`; grants are in
  [tailscale-acl.md](../platform/tailscale-acl.md) (admin, admin phone, client devices, one shared
  external user, monitoring probe).
- No LAN access: `lan_guard` drops new inbound LAN connections, so the wildcard binds of Apache and
  Collabora are unreachable from the LAN
  ([media over the tailnet](../decisions/media-over-the-tailnet.md)).
- `nft_guard` drops port 9983 everywhere except loopback.
- sshd binds the Tailscale address ([sshd decision](../decisions/sshd-listen-address.md)).
- The Apache wildcard bind is a recorded exception in `listener_metrics_allowed`.

## Configuration Management

Applied from lxc250. Node-specific roles:

- `mariadb_backup`, `mariadb_restore_test`, `mariadb_bind`
- `timezone` - also pins MariaDB's `time_zone` (`timezone_pin_mariadb`)
- `paperless_inbox_scan`
- `tailscale_cert` (group `tailscale_cert_ondisk`)
- `nft_guard` - Collabora port 9983
- `systemd_hygiene` - removes `nfs-common` and `rpcbind`
  ([KE-3](../platform/known-errors.md#ke-3))
- `tailscale_boot_gate`, `ssh_hardening` - sshd pinned to the Tailscale address

Guest baseline: `apt_metrics`, `journald`, `lan_guard`, `listener_metrics`, `node_exporter`,
`nsswitch`, and the `apt-upgrade.yml` playbook. The Nextcloud application itself (version, apps,
`config.php`) is not managed by a role. See [Ansible](../platform/ansible.md).

## Failure Impact

- No file sync, no Nextcloud Talk, no upload path into Paperless.
- User data on vm102 is unaffected. MariaDB lives in the container; the newest verified dump is on
  the `[DB-Backups]` share.
- Recovery: restore the guest backup, or rebuild and restore MariaDB from the dump
  ([MariaDB restore](../../runbooks/database/mariadb-restore.md)).
