# LXC210 – Nextcloud

This document describes the Nextcloud container (LXC210).

## Purpose

- Personal cloud storage and file synchronization
- Self-hosted alternative to commercial cloud services

## Runtime Characteristics

- CTID: 210
- Hostname: nextcloud
- OS: Debian 12 (bookworm)
- Cores: 2
- RAM: 2048 MB
- Swap: 512 MB
- Root disk: 15 GB (local-lvm)
- Unprivileged: yes
- Nesting: enabled
- Onboot: yes
- Startup order: 3 (after storage + monitoring, 20s delay)

## Mount Points

- `mp0`: `/mnt/smb/nextcloud` → `/mnt/nextcloud` (user data on SMB storage)

## Scheduled Tasks

All scheduled work on this node runs from systemd timers, not cron. The Proxmox host
powers down overnight, so a cron entry silently loses every slot it sleeps through;
`Persistent=true` makes the timer run the overdue job at the next boot. A failed timer
run also raises the fleet-wide `SystemdUnitFailed` alert, which cron jobs never did.

- Paperless Inbox cache scan: `/usr/local/sbin/scan-paperless-inbox.sh`
  - Unit: `paperless-inbox-scan.timer` → `paperless-inbox-scan.service`
  - Schedule: `OnCalendar=hourly`, `Persistent=true`
  - Scans Nextcloud file cache for External Storage mounts used by Paperless-ngx
  - Log: `journalctl -u paperless-inbox-scan.service`
  - Managed by: `ansible/roles/paperless_inbox_scan/`
  - See: [Nextcloud Service Documentation](../services/nextcloud.md)

- Nextcloud background jobs: `/etc/cron.d/nextcloud` — `*/5 * * * * www-data php -f /var/www/nextcloud/cron.php`
  - Upstream-owned, not ours, and correctly a cron job: at a 5-minute cadence there is nothing
    for `Persistent=true` to catch up on. Do not migrate it.

- Tailscale certificate refresh: `/usr/local/sbin/tailscale-cert-refresh.sh`
  - Unit: `tailscale-cert-refresh.timer` → `tailscale-cert-refresh.service`
  - Schedule: `OnCalendar=*-*-* 04:30:00`, `Persistent=true`
  - Renews the on-disk cert and reloads Apache only when the cert actually changed
  - Managed by: `ansible/roles/tailscale_cert/`
  - Because the host sleeps through 04:30, `Persistent=true` means this effectively runs at
    **boot**, not at 04:30. It therefore has to tolerate a tailscaled that is up but has not yet
    joined the tailnet: the script polls for the node's MagicDNS name for up to 90 s rather than
    reading it once. Before that was fixed (2026-07-28) the unit failed on every boot and renewal
    never ran — the certificate was simply still valid, so nothing surfaced.
  - See: [KE-16](../platform/known-errors.md#ke-16) and
    [KE-18](../platform/known-errors.md#ke-18-services-start-before-tailscale-is-ready-ordering-is-not-readiness)

## Network / Tailscale

- Tailscale hostname: nextcloud
- Tag: `tag:tier1`
- Accessible by: `tag:admin` (all ports), `tag:tier0` (all ports), `tag:tier1` (all ports), `tag:client` (port 443)

### Tailscale Serve

Not in use. Nextcloud binds to `0.0.0.0` for LAN upload performance (large file volumes).
Apache handles TLS termination on port 443. MagicDNS resolves `nextcloud.<tailnet-id>.ts.net`
to the Tailscale IP; Apache answers the request directly (no Tailscale Serve involved).

See: [Loopback + Tailscale Serve ADR](../decisions/loopback-tailscale-serve.md) — section "Documented Exceptions"

## Security / Exposure

- Classified as tier 1 (security-critical)
- HTTPS via Apache-managed TLS certificates (not Tailscale Serve)
- No public exposure / no router port forwarding
- LAN access permitted for large file uploads (performance trade-off)
- Network policy enforced via Tailscale ACL (node tags + ACL JSON)
- See: [docs/platform/tailscale-acl.md](../platform/tailscale-acl.md)

## Failure Impact

If LXC210 becomes unavailable:

- No file synchronization or cloud access
- User data on SMB storage is not affected
- Local MariaDB is unavailable (database is inside the container)
- Recovery: recreate LXC, reinstall stack, remount storage, restore DB from backup

## Configuration Management

Managed via Ansible from LXC250.

- **Playbook:** `ansible/playbooks/apt-upgrade.yml` — rolling apt upgrade (`serial: 1`)
- **Role:** `ansible/roles/node_exporter/` — deploys node_exporter binary + systemd unit
- **Role:** `ansible/roles/ssh_hardening/` — `PasswordAuthentication no`, `PermitRootLogin no`
- **Role:** `ansible/roles/paperless_inbox_scan/` — deploys `scan-paperless-inbox.sh` + hourly timer (adopted 2026-07-10; previously a hand-written root crontab entry that was lost on every rebuild)
- **Role:** `ansible/roles/tailscale_cert/` — on-disk cert refresh + conditional Apache reload
- **Role:** `ansible/roles/systemd_hygiene/` — masks the permanently failed `run-rpc_pipefs.mount`

See: [Ansible Platform](../platform/ansible.md)
