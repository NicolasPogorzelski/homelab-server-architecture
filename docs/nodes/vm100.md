# vm100 - GPU Compute

Runs the GPU workloads: Jellyfin with NVIDIA transcoding, Audiobookshelf, and `llama-server` as the
always-on fallback inference backend. Media is read from vm102 over SMB.

- Tag: `tag:tier2`

## Resources

- VMID 100, hostname `GPU`, Ubuntu 22.04 LTS, OVMF (UEFI), q35, virtio-scsi-single
- 8 cores, 16384 MB RAM, guest agent on; onboot, startup order 6
- GPU: NVIDIA card passed through as `hostpci0` (primary VGA), driver `nvidia-driver-580-server`
- `scsi0`: 64 GB system disk on `local-lvm` (boot SSD, [KE-14](../platform/known-errors.md#ke-14))
- `scsi1`: `jellyfin-data`, a qcow2 image on the host's aux-disk
  ([KE-13](../platform/known-errors.md#ke-13)), mounted at `/mnt/vm-data`: Jellyfin config, cache
  and metadata, LLM models, CUDA cache and Docker's data root. Marked `backup=0`.
- Snapshots work since the disk became qcow2 on 2026-10-10. They live on the same aux-disk and cover
  a bad change, not the loss of the disk.

## Services

Three Compose stacks under `/opt/docker`, sources in `docker/jellyfin/`, `docker/audiobookshelf/`
and `docker/llama-server/` (image versions there):

| Service | Listens on | Tailnet entry | Details |
|---|---|---|---|
| Jellyfin | `<tailscale-ip-vm100>:8096` | direct bind ([KE-28](../platform/known-errors.md#ke-28)) | [Jellyfin](../services/jellyfin.md) |
| Audiobookshelf | `127.0.0.1:13378` | `tailscale serve --tcp 13378` | [Audiobookshelf](../services/audiobookshelf.md) |
| llama-server | `127.0.0.1:8080` | `tailscale serve --tcp 8080` | [LLM inference](../services/llm-inference.md) |

The two `tailscale serve` forwards are set by hand and persist in `tailscaled`'s state. Because
Jellyfin binds the Tailscale address, `docker.service` waits for it through `tailscale_boot_gate`.

Timers: `jellyfin-cuda-watchdog.timer` restarts Jellyfin when CUDA is lost and no direct stream
would be cut ([KE-10](../platform/known-errors.md#ke-10),
[CUDA watchdog](../services/jellyfin.md#cuda-watchdog)). The root crontab is empty.

## Storage

Media arrives through four systemd automount units, so a mount is attempted on first access rather
than once at boot ([KE-15](../platform/known-errors.md#ke-15)). All four mount read-only from
vm102's LAN address, admitted by `smb_guard` and by `lan_guard` on vm102.

| Unit | Mountpoint | Share on vm102 |
|---|---|---|
| `srv-media-filme.automount` | `/srv/media/filme` | `media-jf-filme` |
| `srv-media-serien.automount` | `/srv/media/serien` | `media-jf-serien` |
| `srv-media-audiobooks.automount` | `/srv/media/audiobooks` | `media-abs-audiobooks` |
| `srv-media-podcasts.automount` | `/srv/media/podcasts` | `media-abs-podcasts` |

`docker.service` is ordered after these automounts and requires `/mnt/vm-data`
(`docker_mount_ordering`). A container whose start fails on a refused CIFS mount is retried once per
boot by `docker_boot_retry` ([KE-27](../platform/known-errors.md#ke-27)). Do not unmount a live CIFS
mount on this node ([KE-20](../platform/known-errors.md#ke-20)).

## Access Model

- Grants are in [tailscale-acl.md](../platform/tailscale-acl.md): Jellyfin and Audiobookshelf for
  admin, client, reader, untrusted and media-player devices and one shared external user;
  `tag:ai-stack` and the monitoring probe on 8080; SSH from lxc250 and the admin workstations.
- sshd binds the Tailscale address only, behind `tailscale_boot_gate`
  ([sshd decision](../decisions/sshd-listen-address.md)). Rollback is the Proxmox web console as
  user `gpu`, or a snapshot taken before the change.
- Break-glass: the admin workstation key for user `gpu` (`breakglass`); `sudo` asks for a password,
  and the account is in neither `docker` nor `lxd`.

### No Media Ports on the LAN

No service listens for LAN clients. Media clients use the tailnet
([media over the tailnet](../decisions/media-over-the-tailnet.md)); `lan_guard` drops new inbound
LAN connections. vm100 uses the LAN only outbound: SMB to vm102 and netconsole to the hypervisor.

`enp6s18` accepts no IPv6 router advertisements (`/etc/netplan/60-no-ipv6-ra.yaml`, role
`netplan_no_ra`), so it holds only a link-local IPv6 address. `listener_metrics` reports any listener
outside the binding rule.

## Configuration Management

Applied from lxc250. Node-specific roles:

- `docker_compose_update`, `docker_mount_ordering`, `docker_boot_retry` (group `docker`)
- `jellyfin_watchdog`, `jellyfin_user_prefs` - CUDA watchdog; subtitle mode held at "None"
- `netconsole` - kernel log over UDP to the hypervisor, `console_loglevel` 7
- `netplan_no_ra` - no router advertisements on `enp6s18`
- `unattended_upgrades` - security pockets only, kernel and NVIDIA packages blacklisted
- `apt_metrics` - with Ubuntu's `apt.sh` collector
- `chrony` - replaces Ubuntu's default `systemd-timesyncd` (group `vms`)
- `breakglass` - group `vms`, `breakglass_user: gpu`
- `systemd_hygiene` - removes the retired media mount units
- `tailscale_boot_gate` (`docker.service`, `ssh.service`), `ssh_hardening`

Guest baseline: `journald`, `lan_guard`, `listener_metrics`, `node_exporter`, `nft_guard` (no ports
here), `nsswitch`, `timezone`, and the `apt-upgrade.yml` playbook. See
[Ansible](../platform/ansible.md).

## Failure Impact

- No media streaming, no fallback inference; OpenWebUI uses the admin desktop while it is on.
- Media on vm102 is unaffected. The guest backup holds the root disk only; `jellyfin-data` (config,
  watch state, models) has no backup and is lost with the aux-disk.
- Recovery: restart the VM, check the automounts and `docker compose ps` per stack.
