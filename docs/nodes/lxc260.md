# lxc260 - PostgreSQL Platform

Runs the central PostgreSQL instance for OpenWebUI and Paperless-ngx, one database and one role per
tenant, with nightly verified dumps to vm102.

- Tag: `tag:database`

## Resources

- CTID 260, hostname `postgres`, Debian 12, unprivileged, nesting on
- 2 cores, 1024 MB RAM, 512 MB swap, 8 GB root disk on `local-lvm`
- Onboot, startup order 2
- No Docker on this node

## Services

- PostgreSQL 15 (Debian package) on `127.0.0.1:5432` and `<tailscale-ip-lxc260>:5432`; data
  checksums on, `fsync` and `synchronous_commit` on
- `postgres_exporter` on `<tailscale-ip-lxc260>:9187`, user `postgres_exporter` with `pg_monitor`
- `pg-backup.timer` - nightly `pg_dumpall`, verified before rename, feeds `PostgreSQLBackupStale`
- `pg-restore-test.timer` - monthly restore into a throwaway cluster, feeds
  `PostgreSQLRestoreTestStale`

PostgreSQL binds the Tailscale address, so it must not start before `tailscaled` has assigned it
([KE-9](../platform/known-errors.md#ke-9),
[decision](../decisions/postgresql-tailscale-boot-ordering.md)). Schedules are in the role defaults;
tenants, `pg_hba.conf` and the backup chain are described in
[PostgreSQL platform](../services/postgresql-platform.md).

## Storage

- `mp0`: `/mnt/aux-disk/postgres` -> `/var/lib/postgresql` - the data directory, on local block
  storage for `fsync` semantics. That disk is the aux-disk
  ([KE-13](../platform/known-errors.md#ke-13)).
- `mp1`: `/mnt/smb/postgres-backups` -> `/mnt/backups` - dumps on the vm102 `[Postgres-backups]`
  share, a separate failure domain from the data directory

## Access Model

- No LAN or wildcard listener; `lan_guard` drops new inbound LAN connections; sshd binds the
  Tailscale address.
- Four layers, each independent of the others: the Tailscale ACL (only the `paperless` host and
  `tag:ai-stack` reach 5432), the Tailscale-only bind, `pg_hba.conf` (`hostssl`, one `/32` per tenant,
  `scram-sha-256`, default reject) and per-tenant roles.
- No workstation reaches PostgreSQL. Monitoring reaches 9100 and 9187; lxc250 reaches 22; this node
  reaches the journal receiver on lxc200 ([tailscale-acl.md](../platform/tailscale-acl.md)).

## Configuration Management

Applied from lxc250. Node-specific roles:

- `postgresql_boot_order` - start gated on the Tailscale address
- `postgresql_provisioning` - declarative tenants from `postgres_tenants` in
  `host_vars/lxc260.yml`; the two live tenants are not adopted yet (empty list)
- `postgresql_backup`, `postgresql_restore_test`
- `postgres_exporter` - unit and its vaulted DSN file
- `journal_upload` - ships the journal to lxc200
  ([exercise scope](../decisions/exercise-scope-before-terraform.md))
- `systemd_hygiene` - retires masks for packages no longer installed
- `tailscale_boot_gate`, `ssh_hardening` - sshd pinned to the Tailscale address

Guest baseline: `apt_metrics`, `journald`, `lan_guard`, `listener_metrics`, `node_exporter`,
`nft_guard` (no ports here), `nsswitch`, `timezone`, and the `apt-upgrade.yml` playbook. See
[Ansible](../platform/ansible.md).

## Failure Impact

- OpenWebUI and Paperless-ngx lose their database and do not start; open connections end.
- Committed data is safe while the data directory is intact.
- Losing the aux-disk loses the data directory; the newest verified dump on vm102 is the recovery
  point ([pg-restore](../../runbooks/database/pg-restore.md)).
- Recovery order: lxc260 first, then the application containers.
