# lxc200 - Monitoring

Runs the platform's observability stack (Prometheus, Alertmanager, Grafana, Blackbox exporter) and
the central journal receiver. It is in no service's data path.

- Tag: `tag:monitoring`

## Resources

- CTID 200, hostname `monitoring`, Debian 12, unprivileged, nesting on
- 2 cores, 1024 MB RAM, 512 MB swap, 8 GB root disk on `local-lvm`
- Onboot, startup order 2
- Kernel TUN for Tailscale (`lxc.cgroup2.devices.allow: c 10:200 rwm` plus the `/dev/net/tun`
  mount entry, [DD-13](../decisions/design-decisions.md#dd-13)); no AppArmor override

## Services

Docker Compose stack in `/opt/monitoring`, source `docker/monitoring/docker-compose.yml` (image
versions live there). All containers use host networking.

| Service | Listens on | Published through |
|---|---|---|
| Grafana | `127.0.0.1:3000` | `tailscale serve` HTTPS 443 |
| Prometheus | `127.0.0.1:9090` | `tailscale serve` HTTPS 9443 |
| Alertmanager | `127.0.0.1:9093`, gossip listener off (`--cluster.listen-address=`) | `tailscale serve` HTTPS 9093 |
| Blackbox exporter | `127.0.0.1:9115` | - |
| node_exporter (container) | `127.0.0.1:9100` | - |
| node_exporter (native unit) | `<tailscale-ip-lxc200>:9101` | - |
| systemd-journal-remote | `<tailscale-ip-lxc200>:19532` | - |

URLs: `https://monitoring.<tailnet-id>.ts.net` (Grafana), `:9443` (Prometheus), `:9093`
(Alertmanager).

Two node_exporters run on purpose. The container reports resources but cannot read the node's
systemd; the native unit on 9101 exports `node_systemd_unit_state`, so `SystemdUnitFailed` covers
this node ([decision](../decisions/lxc200-systemd-visibility.md)).

The Blackbox exporter runs seven service probes, three HTTP on vm100 and four HTTPS behind
`tailscale serve` ([KE-8](../platform/known-errors.md#ke-8)). Scrape jobs are rendered from
`ansible/roles/prometheus_config/templates/prometheus.yml.j2`; see
[monitoring](../platform/monitoring.md).

## Storage

- `mp0`: `/mnt/aux-disk/monitoring` -> `/data`, on the host's aux-disk
  ([KE-13](../platform/known-errors.md#ke-13)). Holds `prometheus/` (TSDB), `grafana/`,
  `alertmanager/`, `containerd/` and `docker-data/`.
- The metric history has no backup; the guest backup covers the root disk only.

## Access Model

- Web services bind loopback and are published through `tailscale serve`
  ([decision](../decisions/loopback-tailscale-serve.md)). The native node_exporter, the journal
  receiver and sshd bind the Tailscale address.
- `lan_guard` drops new inbound LAN connections. Nothing is published to the LAN or the internet.
- Grants to `tag:monitoring` are in [tailscale-acl.md](../platform/tailscale-acl.md): the admin
  workstations reach 443, 9093 and 9443, lxc250 reaches 22 and 9443 (drift sweep), lxc211 and
  lxc260 reach 19532 (journal upload).

## Configuration Management

Applied from lxc250. Node-specific roles:

- `prometheus_config` - renders `prometheus.yml` and deploys `alert.rules.yml` into `/opt/monitoring`
- `journal_remote` - the journal receiver
  ([exercise scope](../decisions/exercise-scope-before-terraform.md))
- `node_exporter` - the native unit on port 9101 (`node_exporter_port` in `host_vars/lxc200.yml`)
- `tailscale_boot_gate`, `ssh_hardening` - sshd pinned to the Tailscale address
  ([sshd decision](../decisions/sshd-listen-address.md))
- Group `docker`: `docker_compose_update` (stack listed in `compose_projects`),
  `docker_boot_retry` and `docker_mount_ordering` (both inactive on this node)

Guest baseline: `apt_metrics`, `journald`, `lan_guard`, `listener_metrics`, `nft_guard` (no ports
here), `nsswitch`, `systemd_hygiene`, `timezone`, and the `apt-upgrade.yml` playbook. See
[Ansible](../platform/ansible.md).

## Failure Impact

- No metrics, alerts or dashboards; no other failure is reported while lxc200 is down.
- Running services are unaffected.
- Losing the aux-disk loses the metric history. Dashboards and rules come from the repository.
- Recovery: restore the guest backup or recreate the container, then run `docker_compose_update`
  and `prometheus_config`.
