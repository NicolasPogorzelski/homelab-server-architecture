# lxc230 - OpenWebUI

Runs OpenWebUI, the web front end of the AI stack, with its database on lxc260 and two
`llama-server` backends on the tailnet.

- Tag: `tag:ai-stack`

## Resources

- CTID 230, hostname `ai-openwebui`, Debian 12, unprivileged, nesting on
- 4 cores, 2048 MB RAM, 1024 MB swap, 16 GB root disk on `local-lvm`
- Onboot, startup order 5, after lxc260
- Kernel TUN for Tailscale ([DD-13](../decisions/design-decisions.md#dd-13))

## Services

- OpenWebUI, Docker Compose in `/opt/openwebui`, source `docker/openwebui/docker-compose.yml` (image
  version there), on `127.0.0.1:3000` (container port 8080)
- Database `openwebui_db` on lxc260, SCRAM over TLS to its Tailscale address
  ([PostgreSQL platform](../services/postgresql-platform.md))
- Inference backends: the admin desktop (primary) and vm100 (fallback), both on port 8080
  ([LLM inference](../services/llm-inference.md))

## Storage

- `mp1`: `/mnt/aux-disk/openwebui` -> `/var/lib/openwebui` on the aux-disk
  ([KE-13](../platform/known-errors.md#ke-13)). The Compose file binds
  `/var/lib/openwebui/data` (app state, `uploads/`, `vector_db/`); `containerd/` and `docker-data/`
  sit beside it.
- No CIFS mount. No database files outside lxc260.

## Access Model

- OpenWebUI binds loopback and is published through `tailscale serve` on 443:
  `https://ai-openwebui.<tailnet-id>.ts.net` ([decision](../decisions/loopback-tailscale-serve.md)).
- `lan_guard` drops new inbound LAN connections; sshd binds the Tailscale address.
- Grants are in [tailscale-acl.md](../platform/tailscale-acl.md): the admin workstations, the admin
  phone and the monitoring probe reach 443; `tag:ai-stack` itself reaches `tag:database:5432` and
  the two backends on 8080.

## Configuration Management

Applied from lxc250. Node-specific roles:

- `tailscale_boot_gate`, `ssh_hardening` - sshd pinned to the Tailscale address
- Group `docker`: `docker_compose_update` (stack listed in `host_vars/lxc230.yml`),
  `docker_boot_retry` and `docker_mount_ordering` (both inactive on this node)

Guest baseline: `apt_metrics`, `journald`, `lan_guard`, `listener_metrics`, `node_exporter`,
`nft_guard` (no ports here), `nsswitch`, `systemd_hygiene`, `timezone`, and the `apt-upgrade.yml`
playbook. The `.env` holding `DATABASE_URL` and `WEBUI_SECRET_KEY` is created on the node. See
[Ansible](../platform/ansible.md).

## Failure Impact

- No AI chat interface. Backends and lxc260 are unaffected; no other service depends on lxc230.
- Chats and settings live in `openwebui_db` on lxc260; uploads and the vector store are on the
  aux-disk and are lost with it.
- Recovery: restore the guest backup or recreate the container, redeploy the stack, check the
  database connection.
