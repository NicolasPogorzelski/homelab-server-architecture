# LXC230 - OpenWebUI (AI Stack)

This document describes the OpenWebUI container (LXC230).

## Purpose

- Central web UI for the AI stack (LLM interaction, RAG)
- First consumer of the centralized PostgreSQL platform (lxc260)
- Tailscale-only access (no LAN exposure)
- Two inference backends connected (admin workstation + VM100)

## Runtime Characteristics

- CTID: 230
- Hostname: ai-openwebui
- OS: Debian 12 (bookworm)
- Cores: 4
- RAM: 2048 MB
- Swap: 1024 MB
- Root disk: 16 GB (local-lvm)
- Unprivileged: yes
- Nesting: enabled
- Onboot: yes
- Startup order: 5 (after database platform lxc260, 20s delay)

## Mount Points

- `mp0`: `/mnt/smb/openwebui` -> `/data/openwebui` (uploads, vector store, backups on CIFS)
- `mp1`: `/mnt/aux-disk/openwebui` -> `/var/lib/openwebui` (local app state, Docker engine data on aux-disk)

Subdirectory layout under `mp1`:

    /var/lib/openwebui/
    ├── data/          -> OpenWebUI application state
    ├── containerd/    -> containerd image store + snapshots
    └── docker-data/   -> Docker named volumes, network metadata

## Installed Services

- Docker CE 29.4.1 + Compose v5.1.3
- OpenWebUI v0.9.6 (`127.0.0.1:3000` -> container port 8080)

## Database Dependency

OpenWebUI uses the centralized PostgreSQL platform service (lxc260).

- Database: `openwebui_db`
- User: `openwebui_user`
- Host: `<tailscale-ip-lxc260>` (lxc260 Tailscale IP)
- Auth: SCRAM-SHA-256 over SSL
- Connectivity verified via End-to-End test

See: [PostgreSQL platform service](../services/postgresql-platform.md)

## Network / Tailscale

- Tailscale hostname: ai-openwebui
- Tailscale IP: `<tailscale-ip-lxc230>`
- Tag: `tag:ai-stack`
- TUN: Kernel-TUN (CT210-pattern: cgroup2 + mount.entry, AppArmor active)
- Accessible by: `tag:admin` (all ports), `tag:tier0` (all ports), `tag:monitoring` (port 9100), `tag:client` (port 443)

## Security / Exposure

- Classified as AI stack (`tag:ai-stack`)
- No LAN exposure (Tailscale-only)
- No public exposure / no router port forwarding
- Remote access provided exclusively via Tailscale (identity-based overlay)
- Network policy enforced via Tailscale ACL (node tags + ACL JSON)
- ACL Rule 5: `tag:ai-stack` -> `tag:database:5432` (PostgreSQL access)
- See: [docs/platform/tailscale-acl.md](../platform/tailscale-acl.md)

## Failure Impact

If LXC230 becomes unavailable:

- No access to AI/LLM interface
- No data loss (database on lxc260, uploads on SMB storage)
- Other services are NOT affected (OpenWebUI is not in any service dependency path)
- Recovery: recreate LXC, redeploy Docker container, remount storage, configure DB connection

## Configuration Management

Managed via Ansible from LXC250.

- **Stack path:** `/opt/openwebui/` - active Compose stack; intentionally outside the repo clone
- **Playbook:** `ansible/playbooks/apt-upgrade.yml` - rolling apt upgrade (`serial: 1`)
- **Role:** `ansible/roles/node_exporter/` - deploys node_exporter binary + systemd unit
- **Role:** `ansible/roles/ssh_hardening/` - `PasswordAuthentication no`, `PermitRootLogin no`
- **Role:** `ansible/roles/docker_compose_update/` (playbook `ansible/playbooks/docker-compose-update.yml`, group `docker`) - updates the node's Compose stack(s) via `docker_compose_v2`: `pull: always` + `recreate: auto` (idempotent - recreates only on image/config change). Stack dirs in `host_vars/lxc230.yml` (`compose_projects`).

See: [Ansible Platform](../platform/ansible.md)
