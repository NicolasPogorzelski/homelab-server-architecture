# lxc250 - Ansible Control Node

Runs Ansible against all ten managed nodes over the tailnet, plus the weekly fleet snapshot and
drift sweep. It is in no service's data path.

- Tag: `tag:control`

## Resources

- CTID 250, hostname `devops`, Debian 12, unprivileged, nesting on
- 2 cores, 2048 MB RAM, 512 MB swap, 8 GB root disk on `local-lvm`
- Onboot
- Kernel TUN for Tailscale ([DD-13](../decisions/design-decisions.md#dd-13))

## Services

- Ansible, run as user `devops` from `/home/devops/git/homelab-server-architecture`
- `fleet-snapshot.timer` and `fleet-drift.timer`, weekly (schedules in the role defaults)
- sshd on the Tailscale address only; no web service, no `tailscale serve`

All Git work flows through pull requests: changes are written on a workstation and reach `main` by
pull request, and this node only pulls (`git pull --ff-only`). It holds no GitHub credential; the
repositories are public and fetched over HTTPS. `preflight.yml`, imported by every state-changing
playbook, refuses to run unless the checkout is a clean `main` equal to `origin/main`
([Ansible](../platform/ansible.md#the-control-nodes-checkout-tracks-main-and-only-main)).

## Storage

- Root disk only, no mount points, on the boot SSD ([KE-14](../platform/known-errors.md#ke-14)).
- Three gitignored artefacts exist only on this node: the vault password file, the real inventory
  (`hosts.yml` beside `ansible/inventory/hosts.yml.example`) and the Ansible SSH key, which opens user `ansible` on the guests
  and root on the hypervisor.
- All three are escrowed off the platform, in an external password manager and on
  paper. The escrow has not been restored from yet
  ([escrow drill](../../runbooks/platform/escrow-restore-drill.md)).
- The guest backup takes this container first.

## Access Model

- sshd binds `<tailscale-ip-lxc250>:22` only, key authentication only, behind
  `tailscale_boot_gate` ([sshd decision](../decisions/sshd-listen-address.md)). Until `tailscaled`
  has its address after a boot, SSH is unreachable; `pct exec 250` on the hypervisor is the fallback.
- `lan_guard` drops new inbound LAN connections. `systemd-resolved` is disabled, so nothing listens
  on 5355 ([MagicDNS decision](../decisions/magicdns-and-systemd-resolved.md)).
- Inbound grants: `tag:admin` on 22, `tag:monitoring` on 9100. Outbound: 22 to every managed node
  including itself, 9443 on lxc200 for the drift sweep; no person's device
  ([tailscale-acl.md](../platform/tailscale-acl.md)). The node advertises its own tag.

## Configuration Management

The node manages itself from its own checkout. Its `ansible` account was created by
`snippets/scripts/bootstrap-ansible-user-lxc250.sh`, because the bootstrap playbook cannot create the
account it connects with. Node-specific roles:

- `fleet_snapshot`, `fleet_drift` - weekly timers for `fleet-snapshot.yml` and the `--check` sweep
  over `ansible/drift-sweep.conf`
- `nsswitch` - `hosts: files myhostname dns`, `systemd-resolved` disabled
- `tailscale_boot_gate`, `ssh_hardening` - sshd pinned to the Tailscale address; the gate replaced
  the former hand-written `ssh.service` override ([KE-18](../platform/known-errors.md#ke-18))

Guest baseline: `apt_metrics`, `journald`, `lan_guard`, `listener_metrics`, `node_exporter`,
`nft_guard` (no ports here), `systemd_hygiene`, `timezone`, and the `apt-upgrade.yml` playbook. See
[Ansible](../platform/ansible.md).

## Failure Impact

- No configuration changes, no fleet snapshot, no drift sweep. Running services are unaffected.
- The Ansible key reaches root on the hypervisor, so this node is the most sensitive guest.
- Recovery: restore the guest backup, or rebuild with
  [lxc250 rebuild](../../runbooks/platform/lxc250-rebuild.md) and the escrowed artefacts.
